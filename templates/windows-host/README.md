# Windows Host Template

Use the installed SDK's `Tools/New-ForsettiProject.ps1` to generate this host together with app-owned app, UI, and service modules. This directory supplies approved scaffold inputs; it does not contain the sealed `ForsettiHostTemplate` library implementation. Keep the installed SDK outside the application's tracked source tree and read its complete `CONSUMPTION_POLICY.md` before integration.

The generated CMake project finds `ForsettiFramework` through its installed package and explicitly declares host/module sources and resources. Its bootstrap registers factories using the same deployed `ModuleManifest` values passed to module constructors. Manifests are copied to `ForsettiManifests` beside the executable, and the host obtains that location from `GetModuleFileNameW`, independently of the current working directory. The application manifest enables the UTF-8 process code page for non-ASCII deployment paths.

Normal launch boots with `ForsettiHostLaunchStrategy::restoreOnly()`. Each native button explicitly activates or deactivates its selected module through the host controller. Runtime registration, compatibility, entitlement, provider, capability, identity, and UI checks remain in that path. The starter uses a static entitlement set for its three generated modules; review the application's production entitlement and capability policies before shipping.

Presentation is an app-owned Win32 window with a native text view created through `IWindowsViewFactory`. The renderer reads the framework surface adapter and presents only the active UI/app module's validated `content` view. It supplies no toolbar, overlay, theme renderer, or complete WinUI implementation. App and UI modules share the runtime's single active surface slot; the service module can remain active alongside it.

`FileActivationStore` writes runtime activation-state updates to `%LOCALAPPDATA%/TemplateHost/activation.json` using a temporary file and replacement. It reports unreadable or malformed state and write failures. Customize state ownership and any multi-instance coordination for the application; this starter does not provide a multi-process state protocol.

Run the built executable with `--verify` to use `FileActivationStore` in a fresh temporary directory whose path includes spaces and Japanese characters. The check covers discovery/registration, initially empty restore-only startup, a denied entitlement before module startup, service/app activation, lifecycle events, UI/app replacement, and visible native app/UI controls. It then checks the desired service/UI selection on disk, shutdown with no active modules and unchanged desired state, a fresh store's disk roundtrip, restore-only reboot with the selected service/UI and visible native UI control, and a second shutdown. Cleanup targets only the two owned activation-state filenames and the empty temporary directory. Read the archive's verification report for executed results; the presence of this check is not evidence that a particular build passed it. Run `Tools/Test-ForsettiIntegration.ps1` on the app-owned source and supply its deployment as `-ShippingRoot` when available.
